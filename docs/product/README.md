# Product Documentation

Product-level intent: what Apex OS is meant to do, what state each area is in,
and what has been deliberately deferred.

## Belongs here

- Roadmaps and execution plans → [`roadmap/`](roadmap/)
- Feature-status boards, module-readiness summaries, pending-work registers,
  known limitations, deferred features → [`feature-status/`](feature-status/)
- Superseded or pre-Apex product lists → [`legacy/`](legacy/)

## Does not belong here

- Implementation reports from a specific fix program → [`../programs/`](../programs/)
- Per-feature technical documentation → [`../features/`](../features/)
- Test evidence → [`../qa/`](../qa/)
- The authoritative feature-to-code map → [`../features/FEATURE_REGISTRY.md`](../features/FEATURE_REGISTRY.md)

## Note on status claims

Documents here are point-in-time. A roadmap or status board is evidence of what
was believed on its date, not a guarantee of current state. The feature registry
is the canonical current view.
